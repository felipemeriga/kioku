# Private production latency probes

`production_chat_latency.py` uses the same authenticated conversation and chat
HTTP endpoints and request parameters as the web app. It measures preparation,
admission, queued execution, streaming, and publication together. It does not use
`NativeRunner` directly or replace production prompts. A successful request must
finish its SSE stream and match the saved assistant message and durable turn.
Success here means transport/publication success, not answer accuracy.

Keep auth, prompts, usage snapshots, deployment proofs, and results outside git.
The auth file contains `access_token` and optionally `api_base` (an HTTPS origin).
The runner never refreshes or rotates shared CLI credentials. The operator must
verify the deployment proof against the live containers before starting.

```sh
uv run --project tsukai python scripts/benchmarks/production_chat_latency.py \
  --auth /private/auth.json \
  --manifest /private/frozen-prompts.json \
  --usage-lease /private/usage-current.json \
  --deployment-proof /private/container-state.json \
  --output /private/new-run-directory \
  --workers 2
```

The output directory must not already exist. Its mode is 0700, and individual
artifacts are 0600. Live `trace-*.jsonl` files expose the newly created test
conversation, turn, and job IDs for server correlation. No uncertain POST is
automatically retried. Original conversations cannot be supplied to the runner;
it creates and labels its own test conversations.

The manifest contains independent conversation chains. Turns within a chain run
sequentially, using only the previous answers generated by this production run.
Do not inject archived assistant answers as prompt facts. For example:

```json
{
  "conversations": [{
    "id": "real-conversation-chain",
    "turns": [{
      "id": "first-turn",
      "content": "Verbatim historical user question",
      "model": "haiku",
      "mode": "agentic",
      "reasoning_effort": "low",
      "timezone": "America/Sao_Paulo",
      "provenance": {"message_id": "historical-message-id"}
    }]
  }]
}
```

Use the original `scope_folder_id` when retained; omit it for the authorized root.
Record any missing historical scope/context or changed effort in provenance.
Freeze identical manifests for before/after runs. Hold concurrency constant and
check other active work, including Mihari. Production currently permits two root
jobs plus a reserved metadata child lane: four requests are a queue/load probe,
not an idle latency baseline. One idle worker measures single-user latency; two
measure a matched parallel workload.

The shared usage lease must contain numeric `five_hour`, `seven_day`,
`observed_at` (Unix seconds), and `account_verified: true`. One operator refreshes
the same lease atomically from the verified subscription meter. Admission fails
closed if the snapshot is missing, malformed, older than 90 seconds, or either
window reaches 75%, preserving headroom below the user's 80% ceiling. Each queued
case and resumed turn rereads it. Admitted requests finish safely. One shared
cross-process coordinator lock prevents competing benchmark batches.

`first_visible_text_seconds` measures the first nonempty SSE text delivered to
the UI, not browser paint or necessarily the final answer. `complete_seconds`
includes durable publication, because production emits `done` after publication.
Server attempt timings and progress frames retain queue/startup/tool durations;
do not infer a precise publication or prefetch span from their residual. Confirm
browser rendering separately and grade answer correctness independently.

After both runs finish, `compare_chat_latency.py --before /private/before --after
/private/after` compares them offline. It refuses changed manifests, concurrency,
endpoint, request/context parameters, resolved model versions, incomplete cohorts,
or unverified publication. Bootstrap audit rows are counted separately from native
tool calls. A changed local date is flagged because relative time questions can
resolve differently. Queue and attempt times remain separate from end-to-end time.

`source_snapshot.py` and `shadow_eval.py` support isolated diagnostic quality runs.
They verify a complete production archive and loaded system-prompt hashes before
inference. Their direct native timings bypass web preparation, queueing, and
publication and must not be presented as browser latency.
