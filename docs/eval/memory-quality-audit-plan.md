# Evaluating Kioku’s agent memory

**Protocol drawn up on 27 November 2026 against Kioku `3636866fc7094606cc1e498ad79eaf3840d72f99`.** The primary question is whether a user can recover the originals needed to answer a question about prior work, within their authorized scope and historical cutoff. This document defines the evaluation. Execution results require a separate run record.

## What to measure

| Layer | Unit and observation | Example failure |
| --- | --- | --- |
| Capture and availability | Source manifest → committed bytes and attachments → parsed events → indexed displayable spans. Count each transition, pending objects and skipped stages. Verify sizes, checksums and a byte-range round trip on known originals. | A signed-in user recalls a session whose original has never reached the archive. |
| Retrieval | An independently identified event, session or set of evidence groups returned by the deployed algorithm. Record discovery ranks and which originals bounded evidence reads expose. | The search finds the request to run a test, while the exit status stays outside the evidence window. |
| Answer | The actual answer a named caller produced from the tool payload, graded against prewritten facts, cited originals, contradictions and justified abstentions. | Both observations are available, but the answer reports a proposal as a successful deployment. |
| Task completion | A named agent follows up across sessions in an executable environment. Use the environment’s adjudicated final state and progress. | The correct earlier constraint is retrieved, but the subsequent booking fails. |

For the first two layers, prioritize a complete selected LongMemEval history, a dialogue with turn-level labels from LoCoMo, and application-specific engineering histories. A weekly or monthly account of work depends on scoped calendar inventory and provenance. Published conversational QA scores cannot establish that behavior. STATE-Bench and MemoryArena address the downstream question of whether memory helps an agent finish work.

## Frozen execution protocol

### Inputs and corpus construction

- Use an isolated checkout and a disposable local database or service. Record baseline SHA, active migration, dataset revision/file hash, local PostgreSQL version, machine, corpus size, cache state, query seed, ranking/caller policy and scope. Keep actual private conversations, gold answers, byte contents, tokens and signed references outside Git. Public dataset rows should also remain outside this repository.
- Freeze a query-only case manifest and a separate gold manifest before scoring. For a sampled run, select stable source IDs through a documented seeded hash within declared strata. Draw LongMemEval by question type with abstentions reported separately. Draw LoCoMo by dialogue or retain all dialogues, then report counts by dialogue and category. Never sample answer-containing turns as the input history. Keep all distractors in each selected history. Distinguish a sample target from the number successfully executed.
- Preserve session boundaries, source roles and record order. Source timestamps take precedence over manufactured timestamps. If a source supplies only session time, document any stable within-session mapping. Namespace independent LongMemEval histories separately. Hide QA annotations, gold IDs, answer strings in metadata, generated summaries, `answer` substrings in source IDs and grading fields from indexed content, query builders and answerers. Keep a private mapping from opaque keys to published anchors.
- Load known transcripts through the archive parser and index publisher, then exercise the actual Python search/read services and SQL functions. A local transport adapter qualifies when PostgreSQL executes the release query and the evidence bytes returned match the fixtures. List each replaced boundary, including authentication, PostgREST, object storage, native capture hooks, HTTP/MCP, or reader model. If ingestion uses direct inserts, measure downstream availability and label capture as bypassed.
- Use a separate unscored plumbing fixture to validate foreign-folder filtering, handling of missing and pending records, stable IDs and correct labels. Freeze all retrieval arms, questions, expansion policy and evidence budgets before the scored run. Disclose exploratory probes undertaken after seeing results. Keep any later remediation on independent validation data.

### Retrieval and grading

| Arm | Fixed action | Measurement |
| --- | --- | --- |
| Literal discovery | User’s original question, relevance order, capped result list. | Ranked first evidence, Any@1/5/10, All@1/5/10 and MRR@10. |
| Product ordering | Same question with default chronological selection. Use an additional explicit latest query for questions about final status. | Hit in the returned page, chronological coverage, identification of the verified outcome. Identify display order when reporting rank. |
| Blind reformulation | Use a bounded caller policy that sees only the question and permitted scope. Freeze terms, max eight alternatives, and the exact policy before scoring. | Paired per-question change with the literal arm, calls made, added latency and evidence bytes. Separate changed queries from all queries. |
| Evidence expansion | Expand the first two distinct selected contexts with one neighbor on each side and a 4,000-character per-record budget. Follow calls/continuations only under a declared separate policy. | Resolution rate, quote/span integrity, evidence recovered only after expansion, observed paired result, forbidden evidence exposure. |
| Native prefetch / answer | Exercise unmodified dispatch, its own extraction of navigation terms and its normal evidence budget. Save exact route, answer, citations and caller identity privately. | Distinguish prefetch eligibility, search, expansion, supported answer, material omission and abstention. Full-path wall time includes all actual calls. |

The cleaned LongMemEval S release has 470 answerable questions. All 470 have at least one turn-level anchor across both roles and 419 have a marked user turn. For 32 answerable questions, the declared session list includes sessions without a marked turn. All 30 abstention rows retain nonempty answer-session lists, and nine also retain positive turn markers. Apply the question-level abstention flag first. Among the 470 answerable questions, 41 have a declared evidence session later than the question’s clock time, always on the same calendar day. An exact-instant cutoff can therefore exclude official evidence. Keep the published haystack intact for this test. On LoCoMo, literal and normalized locator scores need separate labeling if an importer splits concatenated IDs or repairs zero-padding. Validate the mapping before measuring retrieval. The released data also includes image captions on 1,226 of 5,882 turns. Among 1,540 non-adversarial questions, 697 point to at least one caption-bearing turn. Label a text-only importer and avoid inferring that every question touching a caption requires vision. [LongMemEval data](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned/tree/98d7416c24c778c2fee6e6f3006e7a073259d48f) · [LoCoMo data](https://github.com/snap-research/locomo/blob/3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376/data/locomo10.json)

Report separate micro-averages for the selected sample and any class-weighted estimate of the release. For example, selecting 16 answerable questions of each LongMemEval type gives equal weight to types whose full releases range from 30 to 133 questions. The frozen sample score describes that selected mix.

For each required fact, define a group of valid original locators in advance when equivalent observations exist. **Any@k** counts questions with any correct anchor. **All@k** requires at least one anchor from each required group. **Evidence recall@k** is the fraction of required groups covered, averaged per question. **MRR@10** averages reciprocal rank of the first valid hit, assigning zero when absent from the first ten. State whether ranking units are unique events or unique sessions. When collapsing turns to sessions, preserve first occurrence and state how many distinct sessions were observable within the event cap. Never treat an empty gold set as a vacuous All@k pass. For public datasets also report the literal author-provided anchor view, separately from any manually adjudicated alternative.

Check every expanded claim against an independent original locator, expected scope, cutoff and the matching source text. For tool outcomes, distinguish input, result, exit status, remote deployment observation and host/workload. For QA, grade atomic required claims, supported-citation rate, wrong-state rate, confident unsupported assertions on unanswerable cases and correct qualified answers when evidence is incomplete. An answer can be factually correct by chance while its citation fails. Grade evidence retrieval and citation validity independently.

### Operational questions

Prepare private gold evidence for these **question shapes** before runs. Use wholly synthetic records for permissions, temporal controls and injected faults. Public benchmark scores and engineering workflow outcomes have separate populations.

| User question | Required observation |
| --- | --- |
| “What did we actually ship last week across my repos?” | Frozen local Monday–Sunday window, complete expected repository/day inventory, original-only day, actual release observation, plausible unshipped proposal. |
| “What changed this month, and what was still open at month end?” | Dependency across repos and weeks, merge then reversal, in-period evidence, out-of-period correction, possibility of a partial or truncated overview. |
| “Have we ever tried avoiding a full rebuild? What happened on each machine?” | Literal and independently worded versions with different vocabulary, two attempts on different hosts or workloads, each linked to a measured result. |
| “Which tests actually ran, and did the release go live?” | Command + result for each test, skipped/billing-blocked run, independent deployment observation or explicit unknown. |
| “Have we fixed the outage from [date]?” versus “As of [date], what had we verified?” | The incident’s date can differ from the query’s cutoff. Seed an observation after the incident and independently check direct history calls and prefetch. |
| “Remember why we changed this?” and a Portuguese paraphrase | Same evidence and caller scope. Grade history routing, lexical retrieval, expansion and the final answer independently. |
| “What does the vendor spec say, how does our code handle it, and did we test it?” | A document citation, a current code citation and an observed original test result. Attribute each source correctly. Treat unavailable corpora independently. |
| “Did this happen in my other repo?” and “What had we concluded before midnight?” | Cross-owner and sibling-repo decoys, different key scopes, local-midnight/DST and exact as-of-edge records, including a tool result or neighbor just beyond cutoff. |
| “Was the migration approved?” with conflicting or incomplete evidence | Distinguish approved, proposed, attempted, failed, corrected and unresolved. Test an entirely absent fact and an intentionally pending original. |

### Reliability, latency and reporting

1. Record query, corpus and gold hashes, measured time interval, applicable denominators, trial count, committed segments and index-pending counts. Track `no_match`, correct abstention, missing capture, index pending, missing annotation, transport error, provider cap, timeout and skipped control as separate outcomes. Show both all-attempt success and accuracy conditional on a completed eligible request.
2. Measure wall time from caller entry to usable payload. Break out ingestion, search, query planning/reformulation if any, signed reads, caller orchestration and model answer when exercised. Label SQL-only and service-only timings by boundary. Time the first invocation in a fresh process separately, include connection setup when it is inside the boundary, and identify the database/OS cache as unknown unless actually controlled. Use fixed warm-up and at least five repeated warm calls for representative question families. Report median, p95 with sample count and method, maximum, failure rate, calls, response bytes and enough distribution detail to identify slow modes.
3. Report results per source, question class and distinct history. A thousand questions sharing ten conversations do not give a thousand independent histories. Include counts for small strata and paired arm deltas. If reporting uncertainty, resample by conversation/history with a fixed seed and show the number of independent clusters. Repeated trials on one corpus estimate variability under that corpus.
4. Publish a coverage table for all six public benchmarks and each operational requirement. Distinguish reference reviewed, data inspected, corpus ingested, retrieval replayed, answers graded and environment executed. Record deviations, elapsed time, stopping rules and failure examples using redacted IDs. A validated archive locator, a measured QA judgment and a completed task each require their own evidence.

### Backfill and indexing liveness

For a late import, create source events A, B and C in an isolated namespace. A and B have source timestamps before cutoff T. C is after T and pairs with B. First commit/index A and query as of T. Next commit/index B and C, repeating exactly the same query, cutoff and authorization. A record-time implementation can now return B. C must stay outside both discovery and signed expansion. Record the wall-clock instants and index states of both observations so a later reader can distinguish a newly ingested original from a newly occurred event. This control identifies the API's as-of semantics. A historical archive-visibility snapshot would need a stored availability time and a matching query contract.

For maintenance, compare the same number of synthetic committed segments and records distributed over one concentrated session or several sessions. Cross that assignment with one worker or two independent worker connections, preserving tool-result mix, total bytes, segment sizes, initial unindexed state and database settings. Use normal worker entry points, fixed observation windows and fresh isolated namespaces. Test each worker once more after drain and verify that repeated processing preserves event identity and original bytes. Collect time to first searchable event, completed parses and lexical indexes per interval, time to drain, late arrivals, RPC durations and observed SQLSTATEs. Label cases that only call a session worker versus the full cursor-based scheduler. Keep public-query latency measurements separate from the concurrent-load experiment. A lab slowdown under overlap can support a capacity hypothesis; attributing a production backlog requires evidence from that deployment. Their declared answer-bearing session bodies and marked-turn bodies are disjoint. Across all 470 answerable questions, 31 declared answer-session bodies recur. A bootstrap over question IDs describes sensitivity to weighting these questions and cannot establish independent-source confidence. Prefer exact counts on the complete release.

### Interpreting the FactConsolidation first-page result

The executed diagnostic compares accepted answer strings with the complete source text of each of the first ten returned records. The scorer case-folds both sides and accepts a substring in any one record. It does not ask a model to generate an answer. The caller never gets the accepted strings. Signed reads were validated separately; their contents did not enter this metric. An accepted name or value may occur in an unrelated relation or an obsolete statement. Conversely, the first page can identify a bridge entity whose associated fact a second search would recover. The single-page numbers do not establish that an agent could or could not complete the multi-hop reasoning task, that it selected the current fact, or that its citations prove the answer. The official task's substring score applies to a *generated final answer*. [Pinned task metrics](https://github.com/HUST-AI-HYZ/MemoryAgentBench/tree/538026089d1a8a8eff05121d0db89b388f360eba)

A separate post-hoc diagnostic can measure evidence-led follow-up. Freeze a sample by source-ID hash across four sizes and both hop types without selecting successes or misses. Freeze the caller, prompt, scope, record order and budgets. Give the caller the actual question and first-page evidence only. Permit one second search using a bridge term visibly quoted from that evidence, and one signed expansion. Log the locator supporting the bridge, the reformulated query, the second locator, the final answer or abstention, elapsed time and payload bytes. Compare with a same-budget second-page control. A separate grader checks each relation in the chain, whether a later applicable source fact supersedes it, and the final answer. Record the proportion with both links supported alongside the usual final-answer metric. Keep this diagnostic separate from the frozen first-page comparison.
