# Tsukai v1 protocol

Current runtime contract. See [service overview](../README.md) and
[deployment guide](../../docs/operations.md). Schemas in this directory and
`src/tsukai/` are authoritative if an implementation changes.

Private HTTP on port8788. All /v1 and /internal endpoints require `Authorization: Bearer $TSUKAI_SERVICE_TOKEN`. /v1 additionally requires `X-Tsukai-Capability`: HS256 JWT, dedicated `TSUKAI_CAPABILITY_KEY`, issuer `kioku-backend`, audience `tsukai`. Claims are defined in capability.schema.json. Current scope is checked for every request. No user-supplied native session ID, MCP URL, CLI flags or environment.

POST /v1/jobs accepts job-request.schema.json, returns202 `{job_id,status,events_url,result_url}`. Identical `(owner_id,caller,idempotency_key)` returns same job; changed payload409. Signature/ownership/scope/depth conflicts403. Queue saturation503; drain503. Only backend chat profile resumes conversation; every completion and repair gets fresh native session.

GET /v1/jobs/{job_id} returns durable job. GET /v1/jobs/{job_id}/result returns `{job_id,status,result,error}`; result contains `{text,structured,usage,native_session_id}` or null until terminal. GET /v1/jobs?unacknowledged=true returns completed results for caller scope; backend reconciles canonical domain write then POST /v1/jobs/{id}/ack `{consumer,reference}`. Ack is idempotent and conflicting references409.

GET /v1/jobs/{id}/events streams SSE. Last-Event-ID or `after` is numeric per-job sequence. `id: seq`, `event: type`, `data: <event.schema.json>`. DB is replay truth; disconnect never cancels. Types: job.queued, attempt.started, progress, text.delta (provisional), tool.started, retrieval.completed, tool.completed, attempt.failed, job.completed, job.failed, job.cancelled, job.uncertain. Terminal canonical text is job.completed data.result.text, superseding provisional text. Cursor older than retention410; future cursor409. Heartbeat comments15s. GET/result always survives expired replay.

POST /v1/jobs/{id}/cancel persists cancellation, kills process group and records uncertainty when native execution had started. POST /internal/drain blocks admissions, waits up to120s then cancels/reaps. GET /health/live checks process. GET /health/ready checks DB and cached auth state; startup explicit readiness probe is a single native inference, never repeated by health polling.

Tools: native adapter POSTs `/internal/tsukai/tool-capability` to TSUKAI_BACKEND_URL with service bearer and `{job_id,attempt_id,owner_id,folder_ids,tool_allowlist,tool_capability_ref,deadline}`. Backend returns `{mcp_url,capability}` only from server registry. Capability JWT is restricted to active attempt; backend MCP is authoritative for trace events and scope. POST /v1/jobs/{id}/tool-events accepts `{attempt_id,type,data}` for instrumented tool.started/retrieval.completed/tool.completed; only backend caller, active same-owner attempt. Raw native init, thinking, headers, environment and stderr are never published.

Runtime env: TSUKAI_DATABASE_URL (postgresql+asyncpg direct role connection), TSUKAI_SERVICE_TOKEN, TSUKAI_CAPABILITY_KEY, TSUKAI_CAPABILITY_ISSUER=kioku-backend, TSUKAI_BACKEND_URL, TSUKAI_REDIS_URL(optional hint), TSUKAI_WORKSPACE_DIR=/data/workspaces, CLAUDE_CONFIG_DIR=/state/claude, TSUKAI_NATIVE_BIN=claude, TSUKAI_ENTITLED_OWNER_IDS (comma-separated personal-owner allowlist; empty rejects all), TSUKAI_AUTH_PROBE=true. Native credentials remain native env/state only. API fallback absent.

Admission capabilities MUST include `request_sha256`: SHA256 of the submitted raw JSON object encoded with `json.dumps(payload,sort_keys=True,separators=(',',':')).encode()`. The application checks this before default normalization; prepared Mihari calls cannot change prompts or metadata. Grants last at most900seconds. Reads/cancel/replay require a current scope grant; connected streams close at grant expiry and reconnect with renewed authorization. Same shared bearer alone grants no tenant authority. Only backend holds the scope signing key.

`rebuild_from_committed_history` defaults false and is permitted only for backend chat. Normal chat fails409 for uncertain/cancelled/corrupt sessions or changed model/system prompt/folder/tool/CLI policy. Backend supplies committed Kioku history in a newly signed request with the flag true to POST `/v1/conversations/{conversation_id}/rebuild` (or normal admission), creating a new native session/generation and preserving prior generation mappings. Never reuse an uncertain native turn. Result includes accepted `attempt_id`; result response includes original raw `request_sha256`.

After operator native credential rotation, POST `/internal/recheck-auth` with service bearer performs one singleflight recorded readiness inference. Terminal reauth failure does not loop; transient startup dependency failures retry with bounded backoff. Health polling never invokes a model. Database loss pauses claims; stdout drains into a bounded0600 private spool while SQL writes retry. No delta is sent before durable persistence. Uncommitted failure spools are retained privately for at most30days and are never replay truth.

Static pilot admission permits `claude-sonnet-4-6` and `claude-haiku-4-5-20251001`. Additional `claude-` model IDs must match a selectable resolved model in a fresh authenticated catalog; unsupported models and stale dynamic admissions fail before inference. Output controls use `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, `MAX_THINKING_TOKENS`, `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING=1`, max turns, wall/inactivity deadlines and16MiB byte caps. Native CLI structured-output helper inference may add work; these are not a provider billing exactly-once guarantee. Known helper/schema behavior and output cap must be validated on the pinned CLI before pilot traffic.

Usage is `{billing_mode:'subscription',list_equivalent_usd:number|null,input_tokens:number|null,output_tokens:number|null,cache_read_tokens:number|null,cache_creation_tokens:number|null,model_usage:{},counter_segment, counter_reset,complete,attribution,native_total_cost_usd,native_counters}`. Missing values are null. Resumed process counter attribution is explicitly incomplete because reset detection cannot prove that an increasing counter is session-global rather than process-local. No cash subscription spending is inferred from list equivalents.

Apply the Supabase migration as migration owner, then provision a separate `LOGIN NOSUPERUSER NOBYPASSRLS NOINHERIT` role with no memberships and a password stored only in deployment secrets. Run `psql --set runtime_role=kioku_tsukai_runner -f tsukai/ops/grant-runtime.sql` as owner to grant CRUD and table-scoped RLS only on the seven Tsukai tables. Never use the Supabase service_role credential as the runtime database login. Use a direct PostgreSQL/session-mode connection; transaction pooler mode is not supported by this release. Restricted-role PostgreSQL tests apply the shipped migration and prove domain-table denial.

Review fixes: native process-group ownership persists after leader exit, cleanup sends bounded TERM/KILL to remaining descendants and bounds pipe drains. Missing terminal output, foreign/missing init or final session IDs, and terminal-success followed by process failure are uncertain outcomes, quarantining chat until explicit rebuild. Valid terminal evidence/counters survive nonzero exit; they are never auto-published as completed. Native init and final IDs must both match the host-owned native session on the pinned CLI.

`max_tokens` is the requested native **per-inference** output control, passed through `CLAUDE_CODE_MAX_OUTPUT_TOKENS`. Aggregate modelUsage may include multiple harness/tool/schema-helper inferences and can exceed that value; it is not compared with a per-inference cap. Runtime usage states `requested_max_output_tokens_per_inference` and `output_limit_semantics`. No hard aggregate token/billing cap is claimed. Startup readiness uses a1024-token request budget; byte/time/concurrency limits remain independent hard runtime bounds.

GET `/v1/jobs/{id}/usage` returns `{job_id,attempts:[{attempt_id,number,status,model,native_session_id,counter_segment,usage,error}]}` for every attempt, including failed/repair/uncertain attempts. Unknown usage is null. Invalid structured output retains a private, credential-redacted, bounded64KiB diagnostic with invalid response and exact schema paths/errors. A fresh repair receives original supplied evidence plus that diagnostic; private diagnostics never appear in public events/result/usage. Private diagnostics and failed-job prompt/result evidence expire after30days; accounting counters remain attributable.

SQL polling expires queued work independently of free process slots. Root scheduling first prevents an owner's second active root while another owner waits, then chooses aged profile priority (chat2, completion1, metadata child3, plus one level per minute), least recently served owner, and admission order. The maintenance cap counts actual `caller=mihari`, not all completion profiles. The child lane remains reserved and parent-bound.

Deletion is backend-only and durable: POST `/v1/conversations/{conversation_id}/delete` body `{owner_id,conversation_id,action:'delete_conversation'}` requires a backend scope capability with exactly operations `['session.delete']`, profiles `['chat']` and exact raw request digest. POST `/v1/account/delete` body `{owner_id,action:'delete_account'}` requires operations `['account.delete']`, profiles `[]`. These cleanup grants remain usable after subscription de-entitlement, but grant no inference authority. Both return202 `{deletion_id,status:'pending'|'cleaned'}`. GET `/v1/deletions/{id}` with the same current cleanup scope reports progress. Repeating deletion is idempotent.

Deletion first installs a hashed scope tombstone, blocks admissions/reads and persists cancellation. After local execution is reaped, or remote uncertain ownership exceeds lease/kill grace, cleanup deletes scoped job/attempt/event/ack/session payloads and private workspaces/native session artifacts; credential files and unrelated transcripts are preserved. Only hashed owner/scope tombstone keys remain after completion. Failed filesystem cleanup stays pending for retry. The backend product deletion outbox must submit cleanup and poll for `cleaned`; HTTP202 is not a cleanup acknowledgement. Apply followup migration `20261104110000_tsukai_execution_lifecycle.sql` and rerun the idempotent, transactional seven-table grant template before deploying this runtime.

Admin monitoring: GET `/v1/admin/active-sessions` requires a backend-minted capability with `admin:true`, sub `backend`, exactly operations `['runtime.sessions.read']`, empty profiles/folder_ids/tool_allowlist, depth0 and no parents. The backend must validate its existing administrator policy before minting this dedicated read-only capability. Normal owner capabilities never authorize cross-owner monitoring, and an admin read capability grants no inference permission. Response is `{schema_version:1,generated_at,sessions:[{job_id,attempt_id,native_session_id,owner_id,caller,conversation_id,folder_ids,operation,profile,model_requested,native_cli_version,state,started_at,elapsed_seconds,pid}],queued_counts:{total,chat,completion,metadata_child}}`. Only durable running attempts with live leases appear; idle conversation mappings never appear. `state` is starting/running/cancelling/finishing/remote, PID is null when not locally active. Prompts, content, environment, headers and workspace paths are excluded.

Attempt usage also carries observed timing: UTC ISO `started_at`, `finished_at`, `first_event_at`, `first_text_at` (null when absent), plus queue_wait_seconds, elapsed_seconds, first_event_seconds and first_text_seconds. The latter two durations start at durable attempt admission to a process slot and include backend capability/native startup work. They are captured from actual native NDJSON observation, never inferred from generated prose; they do not claim browser render latency. Apply `20261104120000_tsukai_attempt_timings.sql` before this runtime.

PostgreSQL TLS: `ssl=verify-full` (or `sslmode=verify-full`) is translated to an explicit Python `SSLContext` using system CA trust, mandatory `CERT_REQUIRED` and hostname checking. This avoids asyncpg's implicit `~/.postgresql/root.crt` lookup in the readonly nonroot runner. Supabase's database/pooler uses a private CA: provision its public certificate from the official dashboard/vendor HTTPS source, mount it read-only, and set `TSUKAI_DATABASE_CA_FILE=/etc/kioku/supabase-ca.crt` (or explicit DSN `sslrootcert`). The public CA is added to system roots; certificate/hostname verification never falls back or disables. Conflicting CA paths/modes and missing configured CA files fail closed. No credentials or CA private keys belong in Git. Hive binds `TSUKAI_DATABASE_CA_PATH` (default `/root/.config/kioku/runner/supabase-ca.crt`) into the runner read-only. PostgreSQL pools remain bounded to four connections with zero overflow and a five-second acquisition timeout.

Native structured-output transport uses a strict internal `{result: ORIGINAL_SCHEMA}` object. Claude's StructuredOutput tool rejects top-level oneOf/anyOf/allOf even when the schema is valid JSON Schema; nesting the complete original schema preserves all outcome constraints. The adapter relocates document-local JSON-pointer references, requires exactly the transport wrapper, then validates the unwrapped value against the unchanged original schema and completion outcome rules. Product `result.structured` remains the original response body. No external tool permission or turn-limit increase is introduced. A real Mihari fixture with root oneOf failed before inference (native synthetic API400, zero usage), then completed at its original max_turns=1 with the wrapper, no permission denials and full host validation. Stateful structured chat bindings include the transport policy version; plain chat bindings remain unchanged.

Cancellation uses one shared per-attempt signal across API requests, lease heartbeats and shutdown. Repeated signals cannot interrupt native process-group reaping or the durable terminal transaction: both run in shielded cleanup tasks with fixed deadlines, and cancellation cleanup renews the owned lease before committing. Native cleanup remains bounded by process/drain grace; terminal cleanup is capped at20seconds. Database/lease loss still produces explicit uncertainty rather than pretending cancellation committed. Regression coverage overlaps API+heartbeat+shutdown during slow process stop, and sends repeated external cancellations during both reaping and terminal SQL commit.

The same shielded finalizer also owns successful commits, native-error commits and repair jitter, timeout commits and unexpected-error commits. Cancellation during any terminal path is resolved by the persisted cancel flag inside the authoritative SQL transaction; it cannot bypass cancellation handling by interrupting a sibling exception handler. A cancelled invalid-output attempt cannot enqueue its repair.

## Authenticated model catalog

GET `/v1/models` requires the service bearer and a backend capability with exactly
`runtime.models.read`; ordinary job grants do not authorize it. Discovery reads
authenticated native CLI initialization metadata rather than sending a generation
prompt. Responses contain model display/resolved IDs, supported controls, bounded
account metadata, fetch time, and `stale`. Successful metadata is cached for 900
seconds; failures back off for 30 seconds and return the prior catalog marked stale
when available, otherwise 503. Models whose descriptions require usage credits are
marked unselectable. Static pilot allowances remain separate from dynamic catalog
admission. The product exposes this through `GET /api/chat/models`.
